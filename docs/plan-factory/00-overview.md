# 00. Фабрика: задача из трекера → PR без ручной работы

## Цель

Импортировал задачу — дальше Claude Code / Codex сами: план (по желанию),
код, проверки, ревью, QA, исправления и публикация с описанием PR. Человек
вмешивается в трёх местах: утверждает план (если включён), разбирает задачу,
застрявшую в «Нужно внимание», и мёржит.

```
Импорт ─► [План ─► утверждение] ─► Сборка ─► Проверки ─► Ревью ─► QA
   ▲                                  │          ▲                │
   └──────────── находки, ≤ N кругов ─┴──────────┴────────────────┘
                                                   ─► Публикация ─► Документация
                                                   ─► человек: merge / Готово
```

Документ задачи (у Eskhata — PDF по скиллу `eskhata-task-doc`) — часть
«готово»: его пишет агент на последнем этапе, а Convoy показывает на
странице «Документы» рядом с файлами репозитория.

## Что есть сейчас и где рвётся

| Этап | Сейчас | Разрыв |
|---|---|---|
| Импорт | Jira (Cloud v3, Server v2), Linear, Notion, Peshbar | Берутся 4 поля; нет комментариев, картинок, критериев приёмки; нет автоприёма |
| План | — | Нет режима и шага утверждения |
| Сборка | Бриф: спека, задача, связанные, скиллы | Задачи идут в общем checkout; ворктри только у ручных сессий; `setup_command` не выполняется |
| «Этап закончен» | Только выход процесса | Интерактивные агенты не выходят сами; у Codex нет хуков → ревью, QA, очередь стартуют только вручную |
| Ревью | Параллельно с QA | Нет вердикта, находки вставляет человек, одно ревью на сессию, без скиллов |
| QA | Проверки → агент → файл вердикта | Один и тот же бриф для всех проектов, без скиллов; вердикт читается лишь при выходе процесса |
| Цикл исправлений | — | Нет счётчика, нет авто-перепроверки |
| PR | Строитель сам делает `gh pr create --fill`, **до** ревью и QA | Нет описания и шаблона; часть команд (Eskhata) PR сама не открывает |
| Несколько репо | Проект = один `path` | Задача на два репо не выражается |

## Принципы

1. **Каждый этап сообщает о завершении файлом**, который называет Convoy
   (как сейчас вердикт QA). Одинаково для Claude и Codex, терминала и чата.
   Выход процесса — запасной путь.
2. **У каждой роли свои инструкции проекта**: планировщик, строитель,
   ревьюер, QA, автор PR. Скиллы получают поле «роли» и доходят до
   ревьюера и QA. `review_template` становится частным случаем.
3. **Публикует Convoy, а не строитель** — после зелёных ревью и QA, с
   описанием по шаблону проекта. Режим публикации проекта: открыть PR,
   только написать описание (для команд, где PR открывает человек), push.
4. **Ограниченный цикл**: после N неудачных кругов (по умолчанию 2) задача
   уходит в «Нужно внимание», а не крутится бесконечно.
5. **Без автоматического merge** (как и в product-spec).

  (общая локальная БД не выдерживает параллельных прогонов).
