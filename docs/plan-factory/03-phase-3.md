# 03. Фаза 3: масштаб — автоприём, полный импорт, несколько репо, блокировка QA

Решения по умолчанию (2026-10-14, можно поменять): всё включается в
настройках проекта; автоприём только импортирует (запуск — отдельный
переключатель); вложения скачиваются только картинки и документы до 10 МБ.

## 1. Автоприём из трекера

- В привязке проекта к трекеру (`integration-links.json`, `ProjectLink`):
  `intake: { enabled, query, mine_only, run, minutes }`.
- Окно раз в минуту вызывает `intake_tick`: для каждого проекта, у которого
  подошло время, поиск по сохранённому запросу → `import_issues` (уже
  импортированные пропускаются) → при `run` новые задачи встают в очередь
  и очередь запускается. MCP-подключения не поддерживаются (поиск идёт через
  агента).
- Результат и ошибка последнего прохода видны в настройках проекта.

## 2. Полный импорт

- Jira: комментарии (`fields=comment`), вложения (`attachment`).
- Linear: `comments`, `attachments`.
- Комментарии дописываются в описание задачи разделом «Комментарии»
  (последние 20, усечённые), вложения — разделом «Вложения» со ссылками.
- Картинки и документы вложений скачиваются с авторизацией подключения в
  `<data>/attachments/<task>/`; бриф строителя называет локальные пути.
- Критерии приёмки: раздел «Acceptance criteria» в описании переносится как
  есть; отдельные поля трекера — позже. Notion и Peshbar: без комментариев
  и вложений.

## 3. Задачи на несколько репозиториев

- `Task.extra_projects: Vec<String>` — другие проекты Convoy (репозитории).
- С ворктри: в каждом доп. репо создаётся ворктри с той же веткой и
  выполняется его setup.
- Бриф перечисляет репозитории и пути; агент получает доступ к ним:
  Claude — `--add-dir`, Codex — `--add-dir` (в терминале; Codex в режиме
  чата этот флаг пока не получает). Сессии ревью, QA, документации и PR,
  делящие папку строителя, получают те же папки.
- Проверки QA выполняются в каждом репо его `test_commands`. Публикация —
  PR в каждом репо, ссылки на все — в задаче.

## 4. Блокировка QA-окружения

- `Project.qa_environment: Option<String>` — имя общего окружения (у
  Eskhata: `eskhata-local`). Проекты с одним именем делят блокировку.
- Пока один прогон QA (проверки и QA-агент) идёт в окружении, следующий
  ждёт: `QaStatus::Queued`; опрос пайплайна запускает его, когда окружение
  освободилось.

## 5. Тесты

Core: расписание автоприёма, разбор комментариев/вложений Jira и Linear,
бриф и ворктри нескольких репо, очередь блокировки QA.
