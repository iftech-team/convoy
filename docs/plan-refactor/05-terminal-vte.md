# 05. Терминальная подсистема на VTE

Самая важная часть порта и самый большой выигрыш. Разбор того, что именно
исчезает, и того, что требует внимания.

## Что исчезает

| Сейчас | Строк | Почему не нужно |
|---|---:|---|
| `node-pty` зависимость | — | VTE создаёт PTY и форкает сама |
| `@xterm/xterm` + `addon-fit` | — | VTE и есть рендер |
| `terminal:write` IPC | 4 | ввод идёт прямо в PTY внутри процесса |
| `terminal:resize` IPC | 4 | VTE пересчитывает при аллокации |
| `fitActive()` + FitAddon + ResizeObserver | ~10 | то же |
| `term.onData` → `api.write` | 2 | то же |
| `plain()` / `stripVTControlCharacters` | 3 | VTE отдаёт уже отрендеренный текст |
| `entry.tail` как буфер вывода | ~6 | скроллбек хранит VTE |

Плюс бесплатно появляется: поиск по буферу (`search_set_regex`), OSC 7
(рабочая директория), OSC 8 (кликабельные ссылки), sixel, ligatures,
нормальный IME, выделение по regex, доступность для скринридеров.

## Запуск

```rust
let pty = vte::Pty::new_sync(vte::PtyFlags::DEFAULT, gio::Cancellable::NONE)?;
terminal.set_pty(Some(&pty));

terminal.spawn_async(
    vte::PtyFlags::DEFAULT,
    Some(&directory),          // cwd: session.workingDirectory || project.path
    &[&spec.file, &spec.args…],// из launchSpec()
    &env_vec,                  // из accountEnvironment()
    glib::SpawnFlags::DEFAULT,
    || {},                     // child setup
    -1,                        // timeout
    gio::Cancellable::NONE,
    move |result| { /* pid или ошибка */ },
);
```

`spec.file` и `spec.args` приходят из `launchSpec()` без изменений:
`/bin/bash` + `["-ilc", "exec env CLAUDE_CONFIG_DIR='…' claude --resume '…'"]`.
Инвариант 10 (квотирование метасимволов) сохраняется как есть.

### ⚠ Структурное изменение: spawn асинхронный

`pty.spawn()` в Node возвращает объект сразу. `vte::spawn_async` отдаёт pid
в колбэк. Порядок шагов в `start()` (`main.cjs:251–330`) меняется:

```
Сейчас:  spawn → workspace.update() → при ошибке child.kill()
Станет:  spawn_async → в колбэке: workspace.update() → при ошибке killpg(pid)
```

Между вызовом и колбэком сессия должна считаться «запускающейся»:
кнопка Start заблокирована, повторный запуск отбивается. Добавить
`TerminalState::Starting` рядом с `Running` / `Stopping`.

Это единственное место, где порт не механический. Инвариант остаётся тот же:
**если запись в workspace не удалась, процесс не должен остаться жить.**

## Остановка

Сейчас (`main.cjs:stop()`): `process.kill(-pid, SIGHUP)`, через 1.5 с `SIGKILL`.
В Rust — то же самое через `rustix::process::killpg` или `nix::sys::signal::killpg`:

```rust
let pgid = Pid::from_raw(child_pid);
let _ = killpg(pgid, Signal::SIGHUP);
glib::timeout_add_seconds_local_once(2, move || {
    if still_running(id) { let _ = killpg(pgid, Signal::SIGKILL); }
});
```

VTE создаёт дочерний процесс лидером своей сессии, так что pgid == pid.
Инвариант 30 сохраняется: убивается группа, а не только bash.

Выход ловится сигналом `child-exited` → даёт `status` в формате `waitpid`,
код извлекается как `WEXITSTATUS`.

## Сохранение вывода (`history.cjs`)

Сейчас: каждый `onData` дописывает в `entry.tail`, раз в 2 секунды хвост
в 48 000 символов пишется на диск.

Станет: подписка на `contents-changed` с дебаунсом 2 секунды, затем

```rust
let text = terminal.text_format(vte::Format::Text);
```

### ⚠ Исправлено по результатам M0

Изначально здесь был `text_range_format(Format::Text, 0, 0, end_row, -1)`.
**Так делать нельзя.** Замер на живых агентах (`convoy-vte-selftest`):

| Способ | Claude Code | Codex |
|---|---|---|
| `text_format(Format::Text)` | 714 символов | 426 символов |
| `text_range_format(…, 0, 0, upper, -1)` | 31 символ | **0 символов** |

Оба агента рисуют интерфейс абсолютным позиционированием курсора
(`ESC[row;colH`) после очистки экрана. Диапазонное чтение такие строки
не отдаёт, и бриф ревью оказался бы пустым — при том что на экране всё
видно. `end_row` брался из `vadjustment().upper()`, и это тоже неверно:
величина не совпадает с номером последней строки в адресации `text_range`.

Вывод: снимать весь буфер через `text_format`, обрезать до 48 000 символов
уже в Rust. `text_range_format` оставить только если понадобится читать
конкретный кусок, и тогда проверять результат на непустоту.

Отличия, которые надо учесть:

1. **Текст уже чистый.** VTE отдаёт отрендеренное содержимое без
   escape-последовательностей. `plain()` не нужен, но фильтр управляющих
   символов из инварианта 25 оставить — он применяется к вводу, не к выводу.
2. **Это снимок экрана + скроллбек, а не поток.** Сейчас `tail` — именно поток
   байтов; перезаписанные строки (прогресс-бары, спиннеры) попадают в него
   целиком. VTE отдаёт финальное состояние. Для брифа ревью это **лучше**:
   меньше мусора. Но поведение отличается — отметить в README при релизе.
3. **Обрезка до 48 000 символов** делается после получения текста, как сейчас.
4. `set_scrollback_lines(settings.scrollback)` — тот же диапазон 1000–50000.
5. **Альтернативный экран в буфер не попадает** — проверено: содержимое между
   `ESC[?1049h` и `ESC[?1049l` в скроллбеке не остаётся. Это то, что нужно:
   кадры полноэкранного TUI не засоряют бриф.

## Детект `codex resume <uuid>`

Сейчас (`main.cjs:291–299`): регулярка по `entry.tail` на каждом `onData`.

Станет: та же регулярка по тексту из VTE на `contents-changed`. Но:

- Codex печатает эту строку один раз при старте. Если она уедет за пределы
  скроллбека — потеряется. При скроллбеке в 10 000 строк это маловероятно,
  но в первой версии стоит **запомнить факт находки** и больше не искать,
  а также проверять первые ~200 строк буфера, а не только хвост.
- Альтернатива на будущее: `codex` пишет `session_meta` в свой `.jsonl`;
  `transcripts.rs:scan()` уже умеет его читать. Можно сверяться с файлом
  вместо парсинга экрана. Надёжнее, но добавляет зависимость от момента
  записи файла. В первой версии — регулярка, как сейчас.

## Вставка текста (paste / quick commands / feedback)

Сейчас (`history.cjs:paste()`): текст оборачивается в bracketed paste
`\x1b[200~…\x1b[201~` и пишется в PTY через `child.write()`.

В VTE два пути:

**А. `terminal.paste_text(text)`** — VTE сама решает, оборачивать ли в
bracketed paste, по текущему режиму приложения. Claude Code его включает,
значит поведение совпадёт. Но VTE **не** добавит `\r`, и это правильно.

**Б. Прямая запись в PTY fd** — полный контроль, точная копия текущего
поведения:

```rust
let fd = terminal.pty().unwrap().fd();
let mut file = unsafe { File::from_raw_fd(fd) };   // не закрывать!
file.write_all(payload.as_bytes())?;
```

**Решение:** использовать Б, потому что инвариант 25 требует точного контроля
над тем, добавляется ли `\r`, а submit-флаг у quick commands именно это и
переключает. Логика формирования payload остаётся в `core/history.rs::paste()`
без изменений и остаётся покрытой существующим тестом.

Осторожно с владением fd: оборачивать в `ManuallyDrop<File>` или использовать
`rustix::io::write`, чтобы не закрыть дескриптор PTY при дропе.

## Настройки внешнего вида

| Настройка | Сейчас | VTE |
|---|---|---|
| Размер шрифта | `term.options.fontSize` | `set_font(&pango::FontDescription::from_string("monospace 14"))` |
| Скроллбек | `term.options.scrollback` | `set_scrollback_lines(n)` |
| Тема | `term.options.theme = {bg,fg,cursor}` | `set_colors(Some(&fg), Some(&bg), &[])` + `set_color_cursor` |
| Мигание курсора | `cursorBlink: true` | `set_cursor_blink_mode(CursorBlinkMode::On)` |

Применение настроек ко всем открытым терминалам — как сейчас
`applySettings()` обходит `terminals`.

## Состояние агента

`agentStates` в renderer и `entry.agentState` в main приходят из телеметрии
Claude (hooks), не из терминала. VTE тут ни при чём — см.
[06-integrations.md](06-integrations.md). Важно сохранить принцип из
README desktop: **текст терминала не используется для угадывания, закончил
ли агент.** Единственное исключение — детект `codex resume`, который ищет
факт, а не состояние.

### ⚠ `watch_child` при мгновенном выходе

Если процесс завершается сразу (агента нет на PATH — `bash` отдаст 127), VTE
успевает снять PTY **до** того, как отработает колбэк `spawn_async`, и
`vte_terminal_watch_child` падает на ассерте `pty() != nullptr`. Сигнала
`child-exited` тогда не будет вовсе, то есть задача не получит код выхода и
зависнет в `building`.

Решение (проверено): в колбэке спавна смотреть `terminal.pty()`. Если PTY на
месте — `watch_child`. Если нет — `glib::child_watch_add_local(pid, …)`:
спавн выполнен с `G_SPAWN_DO_NOT_REAP_CHILD`, статус ещё можно забрать.
**Ровно один watch на pid** — два приводят к падению процесса, проверено.
